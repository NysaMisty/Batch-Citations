# Project rules

- Maintain this directory as the only editable source. Historical snapshots belong to Git/tags or explicitly archived ZIPs, not parallel working source folders.
- Read `docs/RELEASING.md` before changing versions, building or delivering. Use `scripts/version.py` for runtime/package/installer versions.
- Keep temporary development/build staging only in ignored `dist`. Deliver only verified formal versions in `outputs/当前版本`; do not create or retain candidate-version deliverables. Preserve older formal packages in `outputs/历史版本`. Each formal version must include the unpacked `Word加载项` directory with Install.cmd, the tested DLL, scripts and documentation, verified byte-for-byte against the matching Word ZIP.
- Never publish a formal version without its own passing test evidence and exact addon/DLL/source checks. Stage internally in dist and atomically publish only after verification. Never overwrite a formal version or reuse a release tag.
- Do not push a remote unless the user explicitly asks.
- Preserve existing native citations, range/fingerprint checks, binding identity, staged transactions, verification, rollback and undo.
- The main window opens directly into the same full native library and persistent numbered mapping queue; no standalone selector or second number-choice control. Queue numbers/titles and occurrence/detail entrances share one target. Each valid native selection, clear or reorder validates and commits sparse changes immediately through onApply; null clears, omitted labels retain bindings. Serialize operations, capture targets, invalidate stale snapshots and deduplicate selection/activation events. Failures retain committed mapping. Preserve established advance/skip behavior and target following for clear/reorder while respecting explicit navigation during validation. Keep applied UI mappings across reopening the same unchanged document for the service lifetime, isolated by document identity and fingerprint; cross-restart uninserted mappings use the existing export/import. Selecting references never writes Word; document insertion stays explicit. Layout changes reuse the same native views, filters, mapping and scroll positions; save preference through Zotero.Prefs. Main literature/occurrence panels remain separate 文献列表 / 引用位置 tabs; each tab scrolls its own content internally. The literature tab may use the saved stacked/side arrangement for the native library and numbered queue; narrow windows fall back without merging the two main tabs.
- Confirm new cross-number reference reuse with cancel as the default, including imports. Retain every original label; let citation generation deduplicate by reference identity.
- An occurrence is selectable only when all its numbers have valid, unambiguous mappings. Revalidate before the final write.
- Keep Zotero's native picker and focus mechanisms; do not use permanent topmost state or synthetic desktop input to work around Windows focus rules.
- Prefer isolated programmatic test interfaces. Test profiles must not reuse the user's library or open unrelated Word documents. Restore temporary registration and templates.
- Record actual results and material coverage limits in `docs/TESTING.md` and the current development report. Historical test counts are not current evidence.
