# 编号批量引用 · Batch Citations

实验性 Zotero 插件，版本 0.2.0。把 DOCX 正文中人工确认的 `[1]`、`[2]`、`[1,3]`、`[1–3]` 映射到 Zotero 文献，导出包含动态引用域与参考文献表域的新副本。

这版处理已保存的文件。最后在 Microsoft Word 中使用官方 Zotero 插件刷新，生成正式富文本格式，并检查文献关联。测试范围和已知限制见 [测试说明](TESTING-0.2.0.md) 与 [可行性核查](FEASIBILITY-0.2.0.md)。

0.2.0 新增单窗口按序选文献、编号连续性检查、重复条目阻止，以及工具菜单和插件管理页的绿色 `[1]` 图标。升级后请重新打开插件并扫描原文档。详见 [更新记录](../../CHANGELOG.md)。

## 安装

1. 打开 Zotero，进入“工具 → 插件”（部分版本显示为“附加组件”）。
2. 点击齿轮，选择“从文件安装插件”，选择 `zotero-batch-citations-0.2.0.xpi`。已安装旧版时直接安装新版即可替换。
3. 确认工具菜单出现“编号批量引用…”。
4. Microsoft Word 还需要安装 Zotero 自带的 Word 插件。Word 功能区应有 Zotero 标签。

插件不要求 Python、Node.js、联网服务或 API 密钥。没有自动升级服务，后续版本需手动安装。Zotero 7 要求清单存在更新地址，因此开发包使用保留域名 `example.invalid`；它不会提供任何下载更新。

## 使用

1. 保存并关闭待处理 DOCX，保留原件。
2. 如果文末已有手写参考文献表，先在一个副本中移除旧条目。在“参考文献”标题下独占一行放置 `{{ZOTERO_BIBLIOGRAPHY}}`。没有该标记且没有旧列表时，插件自动在文末追加参考文献表。
3. 在 Zotero 选择“工具 → 编号批量引用…”，选择 DOCX 并扫描。
4. 查看自动显示的编号连续性检查。连续时点击“按序批量选择文献”，在同一个窗口里依次双击文献，或选中后点“加入”；按当前编号逐个填写，最后核对队列并点击“应用全部映射”。也可为每个编号单独点击“选择文献”。
5. 逐处勾选真正的引用位置，或点击“全选可转换位置”后排除数学、数组、序号等普通数字。默认不勾选任何位置。
6. 选择正文引用样式，例如 IEEE 或 GB/T 7714 数字型样式；点击“导出新的 DOCX”，选择不存在的新文件名。
7. 用 Microsoft Word 打开新文件，点击 **Zotero → Refresh（刷新）**。随后把光标放进一处引用，点击 **Add/Edit Citation**，确认弹出的文献与映射一致。
8. 修改一条文献的标题或年份，再次 Refresh，确认参考文献表随之变化后，用 Word 保存。

占位符编号只是原文与条目的对应标签。最终编号、排序、合并范围和作者年份格式由所选引用样式决定。例如先出现 `[3]` 再出现 `[1]`，数字型样式可能把它们排为 `[1]`、`[2]`。

“导出映射”可保存编号与稳定条目 URI 的对应关系。“导入映射”会重新向当前资料库解析这些 URI，不把另一台电脑的本地数据库数字 ID 当作通用编号。导入后仍需核对文献标题。

## 连续编号与重复文献

连续性检查针对上表中的可转换候选编号，去重并按编号排序。例如 `[1]` 多次出现、另有 `[2]` 和 `[3]`，仍判为连续；存在 `[1]`、`[3]` 时显示缺号 `[2]`，禁用批量选择，单独选择仍可用。连续的文档片段如 `[5]`、`[6]` 可以批量选择，同时提醒起始编号不是 `[1]`。受保护位置不参与这项可转换编号检查。

批量选择按实际“加入”顺序对应当前编号，选错后可在队列中修改或清空。关闭或取消窗口会丢弃本次草稿，原映射保持。选择完成后统一应用，窗口不会为每个编号反复打开。

同一个编号可以在正文多处引用同一文献，**不同编号不能映射到同一个 Zotero 条目**。选择重复条目时会显示它已占用的编号，并禁用确认；确认事件也会再次校验。需要把文献移给另一个编号时，先清空原编号映射。

判重依据当前 Zotero 条目身份及 URI；不同条目仅标题相同不会被自动判为同一个。导入与导出也执行判重，导入冲突时不会部分覆盖当前映射。导入仅合入当前文档涉及的编号。旧版允许的重复编号映射在本版会被拒绝。

## 范围

| 情况 | 第一版行为 |
|---|---|
| 主文档普通正文、表格单元格 | 支持；同一标记可以跨多个文字格式片段 |
| `[1]`、`[1,3]`、`[1–3]`、中文逗号或顿号 | 支持；单个范围跨度最多 100，单簇最多 200 个编号 |
| 已有 Zotero 引用或文档设置 | 拒绝，避免重复转换或破坏原关联 |
| 修订模式、未接受的修订 | 拒绝，请先处理副本 |
| 超链接、已有其他域、内容控件、文本框 | 保留，受保护候选不允许勾选 |
| 页眉页脚、脚注尾注、批注 | 保留，另行统计候选数量，不转换 |
| 脚注型引用样式 | 不提供；第一版只做正文引用 |
| 手写参考文献列表 | 不自动匹配或删除；需移除旧条目 |
| `.doc`、`.docm`、加密文件、数字签名、Strict OOXML | 不支持，请先另存普通 DOCX |
| 超过 25 MiB、展开超过 100 MiB、超过 5000 个 ZIP 条目 | 拒绝 |
| 正在编辑的 Word 窗口 | 不直接操作，处理已保存的文件副本 |

## Word 与 WPS

Zotero 官方提供 Microsoft Word 的动态引用集成。WPS 不在官方支持的 Word 处理器列表中，不能从“能打开 DOCX”推导出“能识别并更新 Zotero 引用”。

WPS 保存的普通 DOCX 可以尝试扫描，但仍要通过本插件的结构检查。生成文件的动态更新工作流以 **Microsoft Word + 官方 Zotero 插件**为验收环境。WPS 内的刷新、编辑引用与再次保存均未承诺支持。

## 版本与验证

清单允许 Zotero 7.0 至 10.0.x 安装；这只是安装范围。7.0.32 与 10.0.7 的具体测试结果见 [测试说明](TESTING-0.2.0.md)。8、9、其他小版本和 macOS / Linux 没有因此自动获得测试认证。

本插件使用 Zotero 内部条目、CSL 和窗口 API，并写入与 Word 集成一致的文档域格式。将来 Zotero 更新后需要回归测试，不能无限制声明“7 及以上通用”。

## 开发与复现

开发需要 Node.js 20 或更高版本和 Python 3。安装成品 XPI 不需要这些工具。

```powershell
npm ci --ignore-scripts
npm test
npm run demo
npm run build
```

`dist/` 中生成 XPI 与源码 ZIP。正式 XPI 内仅包含插件文件及 fflate；xmldom 仅供 Node 测试使用。`examples/placeholder-demo.docx` 与 `examples/demo-references.ris` 是合成资料，可导入 RIS 后按标题映射 1、2、3 号文献。

## 卸载

在 Zotero 插件管理器禁用或移除本插件，菜单和窗口会被清理。已导出的 DOCX 使用标准的 Zotero 引用域，后续管理依靠官方 Word 插件。原始文件由你保留，插件不会覆盖它。
