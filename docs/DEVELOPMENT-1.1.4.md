# 1.1.4 引用绑定与自动重编号修复说明

日期：2026-11-04。本文记录实际修复及开发验证；本次没有安装到用户正式环境，也没有提交或推送 Git。原独立验收报告中的失败记录继续保留，不以本说明替代历史记录。

## 修复结果

正常新增引用采用文献 URI 与引用位置维护身份，显示数字交给 Zotero 的 CSL 处理器。原 [1] 后新增 [8] 绑定 H 时，首域保留 A 的 citationID，条目顺序为 A、H；最终显示 [1]、[2]，B～G 顺延。新增已引用文献复用身份，提前重复引用会改变首次出现顺序；普通匹配不能用新文献覆盖已绑定标签。

当前编号与历史输入标签分别展示。二者指向不同文献时必须选择本次编号来源。没有历史插件记录的正常原生引用仍可保留；不要求用户凭显示数字补造历史编号。异常恢复先核验字段图，能够确认时只补记录或完成原事务，不重复插入引用。

## 历史问题与处理

异常样本中，原 A 的 URI 仍在，但官方相邻合并保留了新域的 citationID，并形成 H、A 顺序。原编号恢复与载体 ID 绑定过紧，会造成列表漏掉原 [1]。先前开发候选已加入 URI 回退，本次保留它并完善别名索引、持久引用图及完整性核验。样本的 H、A 历史顺序没有被擅自改写。

独立验收发现的其他缺陷，本轮对应处理如下。

| 问题 | 处理及主要位置 |
|---|---|
| 手写标记在真实 Word 域外却未被识别为相邻 | `WordDocument.Capture` 增加 fieldStart/fieldEnd；`live-core.buildMergeGroups` 使用完整外部范围 |
| 只复制最左域，漏掉其他来源项 | 合并所有源域和标记，按正文顺序复制；相同文献、相同属性才去重 |
| 已选数字绕过旧绑定保护 | `resolveMarkerMapping` 对所有选中标记验证意图，当前/历史冲突要求带 URI 的明确选择 |
| 只核对不同 URI 集合，漏掉重复位置丢失和属性变化 | `citation-state.verifyTransition` 比较逐域、逐项的身份、数量、顺序、稳定属性和引用组外正文 |
| 合并中途删除后抛错，changed 尚未置位 | `WordDocument.Commit` 同时核对实际正文变化，再撤销和验证还原 |
| 原生刷新改变载体后，账本字节不相等而不能最终化 | `Finalize` 提升核验后的账本，不要求它等于刷新前预测的字节串 |
| 事务中断后无法重开 | 日志保存操作前/预期图和新标签；`recoveryPlan` 核验后继续，不再执行插入操作 |
| Refresh/文献表路径缺少完整账本 | 统一使用 `refreshPlan`、后置验证和最终化 |
| CSV 导入仍拒绝重复引用 | 实时模式的选择、校验、导入和导出统一允许同一文献复用；文件兼容模式保留旧约束 |
| 两端继续接受未核验的旧协议 | Word 先 hello，双方核对协议 3 与全部必需能力；旧组件停止写入 |
| 每次恢复重复全文查 URI | 使用规范化 URI 缓存、联合别名索引及 URI→引用索引 |
| 状态文字重复、恢复按钮遮挡 | 沿用普通流状态区，统一问题列表、去重、长文本换行、按钮独立换行与限高滚动 |

真实联测另外发现并修复两处预览问题：citeproc 会向输入项加入内部 `item` 数据，因此传给处理器的数组必须复制；Zotero 7 的已安装样式会缓存处理器，第三个 false 参数不能禁用缓存，因此预览使用无路径的新 `Zotero.Style` 实例。预览不共享 Word 会话的处理器。

## 数据与提交机制

- 文献身份以 Zotero URI 及经 Zotero 证明的合并别名为准，不以标题、裸本地 item.id 或显示数字认定身份。存在歧义时停止。
- 原生引用域保存完整 CSL 数据。版本 2 辅助账本保存 entries、references、occurrences 和 revision；旧版本 1 可读。citationID 是位置载体标识，不被假定为永不变化的文献标识。
- 先读取、计算和预检，再写暂存账本与压缩恢复日志。双份日志替换保留可验证副本；日志有摘要、大小限制与读回检查。
- 本地合并预先解析所有字段和范围，统一从右到左删除，最后改保留域的代码。修订、保护、超链接、内容控件、异常字段和手动自定义引用均有阻断检查。
- 原生刷新返回后重读 Word，验证位置图、文献、条目属性和正文骨架；验证通过才写正式辅助记录，再确认完成。页码、前后缀、suppress-author、author-only 等稳定属性纳入检查，处理器临时属性不作为身份。
- 本地失败可撤销本批并核验原正文、设置及绑定；原生阶段失败保留字段与日志。Word/Zotero 没有涵盖整条异步流程的数据库式原子事务，不能承诺任意中断都自动回滚。实际状态既不等于操作前也不等于预期结果时，恢复会停止。
- 批量窗口内引用结构变化会核对并触发原生刷新，结束后保留窗口；普通文字或坐标移动不触发无意义重排。关闭窗口后使用官方 Refresh，不持续监控全文。

## 兼容范围及未覆盖事项

支持范围为实测的 Windows 桌面 Word 与 Zotero 7.0.32 / 10.0.7。使用 Zotero 内部 WinWord 接口，未来版本需重新验收；不扩展为 WPS、网页 Word、macOS、Linux 或 LibreOffice 的原位编辑支持。

批量重排面向正文中的正常顺序编码引用。脚注/尾注等正文外引用存在时停止批量写入；作者年份、无法确认首次引用顺序的样式及异常自定义字段交给官方功能处理。已有嵌入文献允许保留，无法可靠计算数字的预览会降级，不伪造最终编号。

原生 Add/Edit Citation、Document Preferences 的每个按钮和所有页码/作者属性组合，没有逐一人工测试。操作系统 DPI/主题、断电和进程崩溃组合也未穷尽。测试通过不能解释为任意文档和任意中断均无风险；已有异常文档仍需按明确诊断核对。
