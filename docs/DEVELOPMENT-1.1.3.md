# 1.1.3 实现与验证说明

本轮保留 Word COM 桥接、本地认证端点、Zotero 引用字段及 CSL 排版架构。修改集中于窗口状态、绑定恢复、快照复用与选择器按钮。

## 窗口生命周期

Word 通过单次 Windows 消息接收任务变化。旧实现仅在通知到达后释放取消的任务；入口如果早于通知被点击，会向已关闭窗口执行 focus，并忽略返回的 cancelled 状态。还有更早的窗口：Zotero 已显示界面，但 start 响应尚未回到 Word，此时 Word 还没有 jobID，重复入口直接返回。关闭、再点入口的意图因而丢失，稍后只处理了旧任务取消。

新入口保留网络请求期间的再次打开意图；首个状态返回后，若旧任务已取消就释放并重新打开，若窗口仍有效则仅聚焦。请求序号避免旧 focus 响应清除较新的用户意图。已有 jobID 的终态也会直接释放重开；服务同时清理没有有效窗口的 pending 任务。

窗口拥有者在真实页面关闭时独立取消任务。主控制器、选择器和窗口拥有者均区分自己的 document 与子页面/初始 about:blank 的 unload；取消可重复执行，不影响 ready/running 的已提交事务。原有原生文献表完成 Promise、事务 nonce、操作代数及旧完成确认隔离继续保留。

1.1.2 的原有 42 项文献表矩阵在本机通过。补充快速关开测试后实际捕获了 start 尚未返回时取消并重开的失败。新增测试进一步把首次响应延迟 1800 ms，并抑制一次取消通知，检验“窗口已关但 Word 仍在等待打开响应”的恢复路径；同时在原生文献表后连续六轮关开，检查任务、窗口和绑定。延迟和通知抑制只存在于隔离测试运行器。

## 原编号绑定

Word 的 `ZBC_BINDINGS_1…N` 分段属性保存版本 1 的绑定记录：每个原编号对应稳定 URI 与 citationID 集合，不保存以显示编号推断的映射。属性与引用插入在同一批事务中更新；异常时恢复原 Zotero 设置、绑定属性和引用正文。

重开时读取现存引用字段：已删除 citationID 不再占用位置；仍存任一对应字段就恢复并锁定原编号。字段 URI 与记录冲突、重复编号抢占同一条目或元数据损坏时停止普通匹配，避免默默选择一个结果。新引用追加 citationID，已有引用字段不被批量流程改写。

主表锁定已提交编号，按序队列跳过并禁止清空/修改这些编号；导入和服务端计划也执行同一检查。仅靠禁用界面按钮不能构成数据保护。用户通过官方引用编辑明确更换文献后，如果字段与原记录不一致，普通匹配暂停，并通过恢复入口再次明确确认原编号；不自动推断更换后的对应关系。恢复不替换已经编辑过的引用字段。

旧版本未持久化原编号，CSL 又可能重排或合并编号，因此不存在可靠的自动逆映射。明确恢复入口逐篇询问原编号、展示汇总并确认，随后提交零插入操作的元数据事务及官方刷新。取消不写入。未恢复的旧版文档禁止普通批量写入。官方手工编辑造成记录与多个重复引用不一致时，也要求先核查，不能靠普通批量匹配覆盖。

## 实际扫描开销和触发

旧实现每次打开创建新扫描对象；事件检查先导出正文 XML 比较摘要，实际变化时 Capture 再次导出 XML。候选扫描还逐段读取保护边界、按不同标记执行 Word Find。连续性计算本身只是小规模数字集合运算，不能把这些 COM/XML 开销归到连续性算法。

1.1.3 对同一 Word 文档保留最后一次候选快照。重开比较正文、域代码/结果和范围、超链接/内容控件边界、Zotero 设置及绑定数据的内容签名；未变时复用候选，并刷新本次选择范围与完整写入摘要。缓存只在内存保留一个最近文档，不写磁盘缓存。

文档选择/激活、进程内可访问性值与选择事件触发 650 ms 防抖。正文/域内容未变就停止，不导出 XML、不重扫；实际变更才重建快照。界面的控件启用、文献选择与列表重绘复用本次编号检查结果。没有持续高频轮询。原生操作或绑定变化会改变签名，提交前始终校验完整 XML 摘要和实际范围。

纯格式编辑不要求重新查编号；重新打开会更新完整写入摘要，若在窗口打开期间改变格式，提交会拒绝旧计划，重开后可继续。第三方宏完全静默修改的路径不能保证即时通知，完整提交校验仍会阻止旧范围写入。

## 原生调用和焦点

[Zotero 官方 integration.js](https://github.com/zotero/zotero/blob/main/chrome/content/zotero/xpcom/integration.js) 的 displayDialog 使用 window watcher 创建无父窗口的对话框，再调用 `Zotero.Utilities.Internal.activate(window)`。它还管理官方 currentDoc/currentWindow 及清理 Promise；这些状态属于一次原生引用操作，不能为了显示本插件选择界面而伪造或占用。

旧 Word 桥接的 AllowForeground 除授予前台权限，还显式 ShowWindow/SetForegroundWindow 到 Zotero 主窗口；批量界面又作为主窗口子窗口创建。因此即使目标是选择界面，也会明显弹出资料库窗口。

新桥接只授予进程前台权限；批量界面复用原生窗口 watcher 和定向 activate，显式传递 wrappedJSObject 参数，不要求主窗口置前。插件不隐藏、不最小化或恢复资料库窗口，也不接管官方 currentWindow。文献选择仍使用原生 selectItemsDialog；实际写入后的刷新仍使用官方 Integration Interface。

Windows 前台保护可能使程序化测试或后台触发只能闪烁任务栏，无法保证任何场景都取得前台。真实 Word 点击提供前台授权；实现只请求目标插件窗口，不通过恢复主窗口绕过系统规则。Zotero 必须已运行，且目前没有覆盖上述批量原编号工作流的独立稳定公共 API。
